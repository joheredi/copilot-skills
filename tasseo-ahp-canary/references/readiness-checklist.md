# Operational readiness

This is a reusable qualification checklist, not a current release-status record.
Read live evidence; record pending work and outcomes in a timestamped handoff
outside the package. An enabled policy/schedule is not a qualified deployment.

| Gate | Type | Evidence required |
| --- | --- | --- |
| Unattended refresh | Process / validation | Prefer two consecutive genuine scheduled cycles with complete/uncapped/unskipped intake, exact 92/690 snapshot, advancing dated evidence and non-provisional native reader publication |
| GitHub route approval | Process / authorization | Approved destination, permissions, disclosure contract and triage owner |
| Delivery qualification | Configuration / validation | Authorized genuine live occurrence or isolated test; issue creation/adoption, persisted association, continuous-violation/retry deduplication, closure/re-alert behavior |
| Failure and recovery | Process / validation; implementation only if needed | Existing evidence or isolated exercise proves incomplete intake/failed publication retains last-good state, exposes failure/staleness and recovers only after genuine success |
| Operations | Process / documentation | Named owner/backup, freshness expectation, checks, triage/manual recovery, retry and rollback procedures |
| Target environment | Deployment / sign-off | Explicit target and authority; dependencies, policy, permissions, schedules, compiler capability and native artifact verified there |

Do not induce live failures, fabricate report facts, or create external issues
merely to make the checklist pass. If no eligible live alert is available,
delivery qualification remains pending unless an isolated test is authorized.

The hourly watchdog changes clock/reader state, not benchmark intake or
operator notification. If independent failed/missed-refresh notifications are
deferred, record explicit operational acceptance and assign a manual check.
Visible staleness is not proof that someone was notified.

Check recovery settings and teach operators the actual workflow. Alert
evidence may precede whole-report publication; explain that distinction.
Measure retained-ledger row/byte growth separately from the 92 selected Frames.
Do not truncate acquisitions or discard the committed revision to pass budgets.

Completion-driven intake and cross-alert investigation grouping are optional
enhancements, not automatic prerequisites for readiness. Reassess only against
observed reliability/latency needs and explicit approval.

This skill operates Staging. Readiness does not authorize Production operations,
nor does a Staging repair establish a Production capability. Hand off actual
deployment to the authorized release workflow and verify target-local evidence.
